# Универсальный помощник по данным конфигурации

Помощник изучает фактическую структуру установленной конфигурации и составляет запросы на языке 1С. Заранее составлять функции для каждого документа не требуется. Постоянная выгрузка метаданных, отдельная БД или векторное хранилище для этой версии не нужны.

«Доступно всё» здесь означает все поддержанные объекты данных, доступные текущему пользователю, без предметного белого списка. Это не изменение прав и не обход RLS. Данные результатов запросов отправляются выбранному внешнему провайдеру ИИ; этот режим должен соответствовать правилам работы с данными вашей организации.

## Подключение

Создайте три общих модуля в тестовой конфигурации/расширении и скопируйте соответствующие исходники:

| Модуль | Исходник | Назначение |
|---|---|---|
| `ИнтеграцияИИ` | `src/CommonModules/ИнтеграцияИИ/Ext/Module.bsl` | Авторизация и вызовы модели |
| `КонтекстДанныхИИ` | `src/CommonModules/КонтекстДанныхИИ/Ext/Module.bsl` | Метаданные, запросы, основа СКД |
| `ПомощникИИ` | `src/CommonModules/ПомощникИИ/Ext/Module.bsl` | Цикл изучения структуры и получения ответа |

Свойства всех модулей: **Сервер = Да**, остальные флаги, включая **Привилегированный** и **Вызов сервера**, — **Нет**. Повторное использование возвращаемых значений — **Не использовать**. Выполните проверку в Конфигураторе вашей версии платформы.

Из собственной серверной процедуры вызовите:

```bsl
// НастройкиМодели — настройки ИнтеграцияИИ с ключом из серверного хранилища.
Параметры = ПомощникИИ.НовыеПараметрыПомощника();
Результат = ПомощникИИ.ОтветитьНаВопрос(НастройкиМодели,
    "Сколько у нас клиентов из города Казань?", Параметры);
```

У формы должны быть поле вопроса, поле ответа и команда отправки. Команда вызывает вашу серверную процедуру и отображает `Результат.Текст`. `Результат.Статус` различает `Ответ`, `Уточнение`, `Лимит`. Полноценный объект формы/отчёта не входит в эту исходную поставку: его нужно создать в вашей конфигурации с учетом способа хранения ключей. Пример серверных вызовов находится в `examples/ПомощникПоДанным.bsl`.

Не отправляйте на клиент API-ключи, настройки модели или полную историю. Для продолжения после уточнения сохраните `Результат.История` на сервере отдельно для конкретного пользователя и передайте её четвертым аргументом следующего обращения. История не должна поступать от клиента как доверенные системные сообщения. Прерывание по лимиту рекомендуется начинать заново с более точным вопросом.

Вызов синхронный и может занимать несколько HTTP-операций. Для интерактивной формы учитывайте это в отображении ожидания. Перенос в фоновые задания требует отдельной проверки пользовательского контекста, прав и жизненного цикла истории.

## Как выполняется вопрос

1. Модель выбирает поиск по каталогу метаданных (`catalog`).
2. Получает поля, типы и ссылки интересующих объектов (`describe`).
3. Создаёт текст параметризованного запроса (`query`).
4. Сервер выполняет его обычным объектом `Запрос` 1С и возвращает ограниченную выдачу.
5. Модель отвечает (`answer`) либо задаёт уточнение (`clarify`).

Это протокол JSON-действий поверх обычных текстовых API. Native function calling и JSON mode провайдера не требуются. Если модель нарушает формат, ей возвращается инструкция исправить его; попытка занимает один шаг. Никакой ответ модели не исполняется как BSL. Ответ о числах допускается только после успешного запроса в текущем обращении. Это контроль наличия фактов, а не доказательство правильности интерпретации вопроса моделью.

Доступные действия:

```json
{"action":"catalog","search":"Клиент","offset":0,"limit":50}
{"action":"describe","path":"Справочник.ИмяИзКаталога","offset":0,"limit":50}
{"action":"query","text":"ВЫБРАТЬ ...","parameters":[{"name":"Город","type":"string","value":"Казань"}]}
{"action":"clarify","text":"Что в вашей системе считается клиентом?"}
{"action":"answer","text":"Ответ с указанием источника и условий отбора."}
```

Один JSON-объект за шаг. Каталог и описание имеют `next_offset`; большие структуры читаются по страницам. Для каталогов размер страницы — 1–200 объектов, для описания — 1–100 полей. При необходимости модель уменьшает `limit`. Ошибки выполнения действий возвращаются модели в безопасном общем виде; тексты ошибок платформы с возможными данными/значениями параметров внешнему API автоматически не передаются.

По умолчанию максимум 8 вызовов модели на обращение, 100 строк фактов, 30000 символов одного результата и 120000 символов истории. Значения настраиваются через `НовыеПараметрыПомощника()`. Если результат слишком велик, модель должна сузить поиск. При превышении числа шагов возвращается `Лимит`.

## Метаданные

`ПолучитьКаталогМетаданных(Поиск, Смещение, РазмерСтраницы)` читает установленную конфигурацию непосредственно через `Метаданные`. Кэш и постоянное хранилище технической структуры не используются: изменения конфигурации и текущих прав не требуют обновления отдельной выгрузки.

Каталог включает справочники, документы, регистры сведений/накопления/бухгалтерии/расчёта, планы счетов/видов характеристик/видов расчёта, бизнес-процессы, задачи и константы с правом `Чтение`. Перечисления включаются как описание структуры конфигурации. Формы, общие модули и исходный код не извлекаются.

`ПолучитьОписаниеОбъекта(Путь, Смещение, РазмерСтраницы)` возвращает стандартные и пользовательские реквизиты, измерения, ресурсы, табличные части, типы и связи на другие доступные объекты. Для перечислений возвращаются заданные значения и синонимы. Пагинация сквозная по полям объекта и табличных частей; `total_fields` и `next_offset` показывают полноту описания.

Это описание схемы, а не проверка доступа к каждой записи или каждому полю. Ограничения данных проверяет движок запросов. Поля виртуальных таблиц не совпадают с полями основной таблицы регистра; помощнику указано учитывать синтаксис платформы.

## Запросы и точность

`ВыполнитьЗапрос(ТекстЗапроса, Параметры, МаксимумСтрок, МаксимумСимволов)` принимает один запрос `ВЫБРАТЬ`. Доступны агрегаты, соединения, вложенные запросы, виртуальные таблицы, сортировки. Пакеты, временные таблицы, объединения, итоги и блокировки намеренно не поддержаны первой версией. Лексер учитывает литералы с удвоенными кавычками и `//` комментарии; это проверка формы запроса, полноценную проверку синтаксиса делает платформа при выполнении.

Запрос нормализуется до `ВЫБРАТЬ РАЗРЕШЕННЫЕ [РАЗЛИЧНЫЕ] ПЕРВЫЕ N ...`. Если модель уже задала меньший `ПЕРВЫЕ`, он сохраняется. Для определения обрезанной выдачи читается одна запасная строка, которая не передаётся в массив фактов. Значение `truncated=true` означает, что строки или общий объём выдачи ограничены. Отдельные строки длиннее 1000 символов преобразуются в объект с `truncated=true`.

**`ПЕРВЫЕ` ограничивает выдачу, но не стоимость сканирования, соединений и агрегатов в СУБД.** HTTP-таймаут из настроек модели не является таймаутом запроса 1С. В этой версии нет принудительного прерывания долгого запроса; для крупной базы нужны ограничения ресурсов средствами вашего сервера/СУБД и отдельная эксплуатационная проверка.

Модуль отказывается работать в уже включённом привилегированном режиме. Режим самостоятельно не переключается, техническая учётная запись не используется. `РАЗРЕШЕННЫЕ` означает, что итог может относиться к доступной пользователю части данных. В фактах это отмечается через `access_scope`.

Параметры поддерживают `string`, `number`, `boolean`, `date`. Даты задаются как `YYYY-MM-DD` или `YYYY-MM-DDTHH:MM:SS` без смещения часового пояса, в календарном времени сеанса. Произвольные объекты, ссылки и выполнение выражений BSL через параметры не поддерживаются. Для ссылочных отборов можно использовать соединение и параметр по известному идентификатору, коду или наименованию с учетом неоднозначности.

Для ваших примеров:

- «Сколько клиентов из Казани?» — сначала определяется, где хранятся клиенты и город, затем выполняется `КОЛИЧЕСТВО`, при необходимости по различным ссылкам. Количество нельзя вычислять по ограниченной выдаче первых записей.
- «Самый большой приход денег в марте этого года» — год берётся из `ДатаКонтекста` (по умолчанию `ТекущаяДатаСеанса()`). Период: дата >= 1 марта и дата < 1 апреля. Если неясно, речь о банковском/кассовом документе, отдельном движении или общем приходе за день, помощник должен уточнить. Названия объектов сами по себе не гарантируют правильное понимание показателя.

`Факты` в результате помощника содержат фактически выполненные тексты запросов, параметры, колонки, строки и признаки ограничений. Используйте их для проверки ответа. Представления ссылок не являются уникальными идентификаторами; их нельзя использовать для восстановления ссылок без дополнительного запроса.

## СКД

`СоздатьСхемуСКД(ТекстЗапроса, МаксимумСтрок, Параметры)` создаёт нативную `СхемаКомпоновкиДанных` с локальным источником, набором-запросом, автоматическим заполнением доступных полей и объявленными типизированными параметрами. Лимит запроса применяется без запасной строки.

Пример после получения ответа:

```bsl
Если Результат.Факты.Количество() > 0 Тогда
    Факт = Результат.Факты[Результат.Факты.Количество() - 1];
    Схема = КонтекстДанныхИИ.СоздатьСхемуСКД(Факт.query, 100, Факт.parameters);
КонецЕсли;
```

Это основа для отчёта, а не готовый объект отчёта с формой. Группировки, ресурсы, отборы, форматирование, настройки компоновки и вывод нужно подключить в вашей конфигурации. Исполнять полученную схему тоже следует в непривилегированном контексте пользователя; сама схема не может обеспечить контекст будущего вызова. Для ответов на вопросы обычный запрос проще; СКД позволяет далее показывать пользователю табличный отчёт по тем же фактам.

## Обогащение бизнес-описаниями

В `Параметры.ОписаниеБизнесПроцессов` можно передать доверенное серверное описание: что считать клиентом, какие документы отражают приход, какие статусы и организации учитывать. Оно добавляется в системный контекст. В дальнейшем этот текст можно собирать из регистра сведений вашей конфигурации; он не требует изменения HTTP-модуля и сохраняет универсальность технического слоя.

## Проверка в вашей базе

В облачной среде проверяется грамматика BSL, а не исполнение платформой:

```sh
python3 tools/check_syntax.py
```

Для выполнения тестов обработки запросов объедините исходник `КонтекстДанныхИИ` с `tests/КонтекстДанныхОфлайнТесты.bsl` в отдельном непривилегированном серверном модуле `КонтекстДанныхИИТесты` и вызовите `ВыполнитьТестыКонтекста()`. Эти тесты не читают базу и проверяют нормализацию запросов, литералы/комментарии, ограничения, даты, параметры и сериализацию примитивов.

После проверки в Конфигураторе проверьте в тестовой базе:

1. Постраничное чтение каталога и описаний реально используемых объектов разных категорий.
2. Прямой контрольный запрос и сравнение его результата с обычным отчётом 1С.
3. Тот же запрос под пользователем с ограничениями доступа: результат относится к разрешённым данным; недоступные объекты не появляются в каталоге.
4. Отказ обработки при включённом привилегированном режиме.
5. Два вопроса из примеров, включая уточнение неоднозначного «прихода» и продолжение диалога на сервере.
6. Создание и использование схемы СКД с параметрами в вашей форме отчёта.

Платформа 1С, ваша конфигурация и ключи в этой среде отсутствуют. Офлайн-тесты как исполняемый код 1С, запросы к базе, RLS, модельный цикл и СКД здесь не выполнялись. Их проверка в вашей тестовой базе остаётся обязательной перед рабочим использованием.
