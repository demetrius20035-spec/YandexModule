# ИнтеграцияИИ для 1С

Общий серверный модуль на встроенном языке 1С, без Python, SDK, БСП и сторонних библиотек в рабочей конфигурации. Объединяет текстовую генерацию, историю диалога и получение доступных моделей. Рассчитан на платформу **1С:Предприятие 8.3.18+**; проверку в вашей версии платформы выполняйте в Конфигураторе.

## Универсальный помощник по данным

Добавлены модули `КонтекстДанныхИИ` и `ПомощникИИ`: чтение актуальных метаданных, генерация и выполнение запросов в контексте пользователя, цикл JSON-действий модели и создание основы схемы СКД. Без предметного белого списка объектов. Подключение и ограничения описаны в [инструкции универсального помощника](docs/УниверсальныйПомощник.md).

## Подключение транспортного модуля

1. В конфигурации или разрешённом поставщиком расширении создайте общий модуль `ИнтеграцияИИ`.
2. Установите свойства: **Сервер = Да**; **Глобальный, Клиент (управляемое приложение), Клиент (обычное приложение), Внешнее соединение, Вызов сервера, Привилегированный = Нет**. Повторное использование возвращаемых значений: **Не использовать**.
3. Скопируйте содержимое [`Module.bsl`](src/CommonModules/ИнтеграцияИИ/Ext/Module.bsl). Это исходник модуля, а не полная XML-выгрузка конфигурации: автоматическая загрузка каталога через «Загрузить конфигурацию из файлов» не предусмотрена.
4. Выполните проверку модуля в Конфигураторе и обновите конфигурацию базы данных.
5. Вызывайте модуль из серверного кода вашей конфигурации. Обращение из формы выполняйте через свою серверную процедуру, которая получает ключ из защищённого хранилища и проверяет права пользователя.

Не передавайте ключи и структуру настроек на клиент, не храните их в исходниках. Способ защищённого хранения зависит от вашей конфигурации; модуль его не навязывает. Привилегированный режим не нужен.

## Поддерживаемые провайдеры

| Значение `Провайдер` | Базовый URL по умолчанию | Протокол / модель |
|---|---|---|
| `Яндекс` | `https://ai.api.cloud.yandex.net/v1` | `/responses`; `aliceai-llm/latest` или `yandexgpt-5.1/latest` |
| `GigaChat` | `https://api.giga.chat/v1` | `/chat/completions`; по умолчанию `GigaChat-2` |
| `OpenRouter` | `https://openrouter.ai/api/v1` | `/chat/completions`; модель задаётся явно |
| `VseGPT` | `https://api.vsegpt.ru/v1` | `/chat/completions`; модель задаётся явно |
| `BotHub` | `https://api.bothub.chat/v1/openai` | `/chat/completions`; модель задаётся явно |
| `OpenAI` | задаётся явно | Любой совместимый `/chat/completions` endpoint |

Все адреса переопределяются через `БазовыйURL`, **без завершающего `/`**. Адреса OpenRouter, VseGPT и BotHub — начальные настройки совместимого API: проверьте действующий адрес и доступные модели в кабинете провайдера. Доступ к их документации из среды разработки ограничен; сетевые интеграционные проверки не выполнялись.

Для GigaChat доступны произвольные имена моделей, включая `GigaChat-2-Pro`, `GigaChat-2-Max`, `GigaChat-3-Ultra`, если их возвращает каталог вашего аккаунта. Для прежнего адреса задайте `https://gigachat.devices.sberbank.ru/api/v1`. OAuth по умолчанию: `https://ngw.devices.sberbank.ru:9443/api/v2/oauth`; он настраивается независимо через `URLАвторизации`.

## Быстрый пример Яндекс

Код выполняется на сервере; `КлючИзХранилища` и `ИдентификаторКаталога` предоставляет вызывающая конфигурация.

```bsl
Настройки = ИнтеграцияИИ.НовыеНастройки("Яндекс");
Настройки.КлючAPI = КлючИзХранилища;
Настройки.КаталогЯндекс = ИдентификаторКаталога;
Настройки.Модель = "aliceai-llm/latest";
Ответ = ИнтеграцияИИ.СгенерироватьТекст(Настройки,
    "Расскажи, что такое общий модуль 1С.", "Отвечай кратко по-русски.");
ТекстОтвета = Ответ.Текст;
```

Для YandexGPT используйте `Настройки.Модель = "yandexgpt-5.1/latest"`. Полный URI `gpt://<каталог>/<модель>` также допустим. Передаются `Authorization: Bearer`, `OpenAI-Project`, `temperature`, `instructions`, `input`, `max_output_tokens`. Текст читается из REST `output[].content[]`, а не только из вспомогательного `output_text` Python SDK. Несколько `system`-сообщений объединяются в инструкции; история `user`/`assistant` сохраняется в `input`.

## GigaChat

```bsl
Настройки = ИнтеграцияИИ.НовыеНастройки("GigaChat");
Настройки.КлючАвторизации = КлючАвторизацииИзХранилища;
Настройки.Scope = "GIGACHAT_API_PERS";
Настройки.Модель = "GigaChat-2-Pro";
Модели = ИнтеграцияИИ.ПолучитьМодели(Настройки);
Ответ = ИнтеграцияИИ.СгенерироватьТекст(Настройки, "Привет! Как дела?");
```

`КлючАвторизации` — готовая base64-строка ключа авторизации из кабинета, **без `Basic `**. Модуль не кодирует её повторно. OAuth использует form-urlencoded `scope`, UUID в `RqUID` и `Authorization: Basic`. Поддержаны `GIGACHAT_API_PERS`, `GIGACHAT_API_B2B`, `GIGACHAT_API_CORP`; scope должен соответствовать вашему аккаунту.

`ПолучитьТокенGigaChat()` сохраняет `access_token` и `expires_at` в переданной структуре. Для повторного использования сохраняйте эту структуру в серверном контексте конкретного пользователя/сеанса. Срок — Unix UTC в миллисекундах, токен обновляется с запасом 60 секунд. Не помещайте настройки в общий кэш между пользователями. При HTTP 401 генерация и список моделей повторяются один раз после обновления токена. Ошибки квоты и прочие ответы автоматически не повторяются.

Можно вместо Basic-ключа заполнить `ТокенДоступа` готовым Bearer-токеном, **без `Bearer `**. Если `СрокДействияТокена = 0`, модуль не знает срок; обновлять такой токен должен вызывающий код. Если срок задан и истёк, нужен `КлючАвторизации`. Принудительное обновление: `ПолучитьТокенGigaChat(Настройки, Истина)`.

## Единый интерфейс и параметры

- `НовыеНастройки(Провайдер)` — структура настроек.
- `НовоеСообщение(Роль, Текст)` — структура `role, content`. Роли: `system`, `user`, `assistant`.
- `СгенерироватьТекст(Настройки, Запрос, Инструкция = "")` — запрос без истории.
- `ОтправитьСообщения(Настройки, Сообщения)` — запрос с историей; нужен хотя бы один непустой `user`.
- `ПолучитьМодели(Настройки)` — массив `data` из `/models` для совместимых провайдеров; Яндекс этим методом не обслуживается.
- `ПолучитьТокенGigaChat(Настройки, Обновить = Ложь)` — OAuth / кэш токена.

Генерация возвращает структуру **`Текст, Модель, Данные`**. `Данные` содержит исходный разобранный JSON, включая `usage`, `finish_reason`, статус и сведения о неполном ответе. Не записывайте его целиком в журнал: там могут быть исходные сообщения. `incomplete` Responses API с непустым текстом возвращает частичный текст; проверяйте `Данные.status` перед использованием. Для Chat Completions проверяйте `Данные.choices[0].finish_reason`, например `length` означает обрезанный ответ.

| Настройка | Назначение / значение по умолчанию |
|---|---|
| `КлючAPI` | Bearer-ключ Яндекс или совместимого провайдера |
| `КаталогЯндекс` | Идентификатор каталога, без зашитого значения |
| `Модель` | Модель провайдера; обязательна для генерации |
| `Температура` | `0.3`; общий диапазон проверки 0–2, конкретная модель может ограничивать его строже |
| `МаксимумТокенов` | `1500`; `max_output_tokens` у Яндекс, `max_tokens` у остальных |
| `Таймаут` | `60` секунд на HTTP-операцию; OAuth и повторный запрос могут увеличить общее время |
| `ПроверятьНенормативнуюЛексику` | `Истина`; передаётся как `profanity_check` только GigaChat |
| `ФайлСертификатовУЦ` | Путь к доверенному PEM bundle на сервере 1С; пусто — доверие по умолчанию платформы |
| `HTTPReferer`, `НазваниеПриложения` | Необязательные `HTTP-Referer` и `X-Title` для OpenRouter |

Для OpenRouter / VseGPT / BotHub заполните `КлючAPI` и точный идентификатор модели из `ПолучитьМодели()` или кабинета. Примеры истории и всех сценариев находятся в [`examples/Использование.bsl`](examples/Использование.bsl).

Поддерживаются синхронные текстовые запросы. Streaming, изображения, инструменты/function calling и специальные параметры reasoning-моделей не реализованы. Совместимая модель должна принимать `temperature` и `max_tokens`; модели с обязательным `max_completion_tokens` требуют отдельного адаптера. Полный HTTP-ответ ошибки не включается в исключение, чтобы не раскрывать ключи или текст запроса. Код HTTP сохраняется в безопасном сообщении ошибки.

## HTTPS и сертификаты

Проверка сертификатов **включена**, аналога `verify_ssl_certs=False` нет. Для Сбера установите необходимые официальные корневые/промежуточные сертификаты в доверенное хранилище, используемое вашей платформой, либо укажите PEM bundle:

```bsl
Настройки.ФайлСертификатовУЦ = ПутьКДоверенномуPEMФайлуНаСервере;
```

Bundle должен содержать доверенные УЦ для всех вызываемых адресов (включая OAuth). Файл читается на сервере, не на клиенте. Используйте официальные источники сертификатов и настройте права чтения службе 1С. Сетевой доступ требуется от сервера 1С к выбранному API по 443 и к OAuth Сбера по 9443. Модуль не отключает TLS и не следует HTTP-редиректам с передачей ключа на другой адрес. Настройки URL должны поступать из доверенного серверного кода, а не от произвольного клиента.

## Проверки

Проверка грамматики исходников, примеров и тестов (Python 3, Java 21+ с компилятором):

```sh
python3 tools/check_syntax.py
```

Скрипт загружает закреплённые версии BSL Parser / ANTLR из Maven Central, проверяет SHA-256 и хранит инструменты во временном каталоге. Рабочей конфигурации 1С они не нужны. Это проверка грамматики, **не компиляция платформой и не выполнение тестов**.

Для выполнения офлайн-тестов в тестовой базе создайте отдельный серверный общий модуль `ИнтеграцияИИТесты` с теми же свойствами. Скопируйте в него сначала `Module.bsl`, затем [`tests/ОфлайнТесты.bsl`](tests/ОфлайнТесты.bsl); вызовите на сервере `ИнтеграцияИИТесты.ВыполнитьОфлайнТесты()`. Такой модуль нужен только в тестовой базе. Тесты проверяют формирование тел запросов, историю, JSON с кириллицей, разбор ответов, OAuth-кэш, URL/порт и ожидаемые ошибки без сети и ключей.

После подключения выполните реальные smoke-проверки в тестовой базе: короткий запрос к каждому нужному провайдеру, список моделей GigaChat и повторный запрос с той же структурой настроек. Проверьте непустой текст, доступность выбранной модели и отсутствие TLS/HTTP-ошибок. В этой облачной среде платформа 1С и API-ключи отсутствуют: проверена грамматика; офлайн-тесты и реальные HTTP-запросы в 1С здесь не запускались.
